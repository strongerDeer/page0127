# 알림·서재 일괄 관리 검토

2026-10-27. 검토안에 따라 알림 선택/읽은 알림 전체 삭제와 서재 기록 선택 공개·비공개·삭제를 구현했다. 아래는 확정한 처리 범위와 설계 근거다.

## 결론과 현재 상태

| 대상 | 현재 | 추가할 기능 |
| --- | --- | --- |
| 알림 | 전체/읽지 않음, 모두 읽음, 한 건 읽음·삭제 | 읽은 알림 모두 삭제, 선택 삭제 |
| 내 서재 | 상세에서 기록 하나 삭제, 보관하기/보관 해제 | 서재 관리 모드, 선택 비공개·공개·삭제 |
| 비공개 목록 | 서재 하단 `나만 보는 비공개 책` 펼치기 | 관리 화면에서 비공개 필터와 선택 공개 |

보기 전환과 일괄 행동은 분리한다. 탭은 조회 범위, `선택`이나 `서재 관리`는 관리 모드 진입이다.

## 알림

일반 모드에서는 `전체 / 읽지 않음` 필터를 유지하고 우측에 `선택`과 더보기 메뉴를 둔다.
더보기에는 `모두 읽음`, `읽은 알림 모두 삭제`를 모아 모바일 버튼 과밀을 줄인다.
선택 모드에는 행마다 체크박스와 `3개 선택 · 현재 불러온 알림 모두 선택 · 선택 삭제 · 취소` 바를 보여 준다.
체크박스 클릭과 알림 본문 열기를 분리해 책 봉투·읽음 처리 동작을 유지한다.
하단 고정 선택 바는 모바일 내비게이션 위에 배치하고 가려지는 본문만큼 여백을 확보한다.

- **선택 삭제**: 사용자가 선택한 ID만 처리한다. `모두 선택`은 처음에는 현재 불러온 목록만 대상으로 명시한다.
- **읽은 알림 모두 삭제**: 페이지 밖까지 서버에서 `user_id=현재 사용자 AND is_read=true`로 처리한다. 읽지 않은 알림은 보존한다.
- 전체 삭제는 실행 요청 시점 이전에 만들어진 알림으로 범위를 고정한다. 새로 도착한 알림을 섞어 지우지 않는다.
- 확인 문구: `읽은 알림을 모두 삭제할까요? 읽지 않은 알림은 남아 있어요.` / `선택한 알림 3개를 삭제할까요?`
- 성공 후 실제 삭제 개수를 알린다. 현재 복구 기능이 없으므로 실제 복구 없이 `실행 취소`를 보여 주지 않는다.
- 필터 변경·선택 모드 종료 시 선택을 초기화한다. 요청 중 중복 실행을 막고, 실패 시 선택을 유지한다.

## 내 서재

소유자에게만 `서재 관리` 진입점을 제공한다. 관리 모드는 책장 조형 위에 체크박스를 얹기보다
표지·제목·저자·독서 상태·연도·공개 범위가 있는 간결한 목록으로 전환하는 쪽을 권장한다.
완독·읽는 중·읽고 싶은 책과 비공개 기록을 모두 찾을 수 있어야 한다.

| 행동 | 효과 | 되돌리는 동선 |
| --- | --- | --- |
| 비공개로 변경 | 기록을 보존하고 타인에게 노출하지 않음 | 비공개 필터에서 선택 공개 |
| 공개로 변경 | 비공개 기록을 다시 공개 | 선택 비공개 |
| 삭제 | 선택 독서 기록과 연결 데이터 삭제 | 현재 복구 기능 없음 |

용어는 `공개 / 비공개`로 통일한다. 상세의 `보관하기 / 보관 해제`는 실제로 `is_public`만 변경하므로
후속 구현에서 `비공개로 변경 / 공개로 변경`으로 맞춘다. 완독 기록의 보관이나 독서 상태 변경과 혼동하지 않게 한다.

### 핵심: 한 권과 독서 기록 한 건은 다르다

`books`는 재독할 때마다 행이 생긴다. `dedupeReadings`는 사용자·독서 상태·ISBN으로 묶고,
선택한 연도와 공개 여부로 나눈 뒤 책장에 대표 한 건만 보여 준다.
대표 ID 하나만 수정하면 화면의 한 권과 실제 처리 범위가 달라진다.

첫 구현은 관리 목록을 **회독별 독서 기록**으로 표시하고 `3개 기록 선택`처럼 실제 단위를 말하는 방식을 권장한다.
연도·상태·공개 범위 필터 안에서 현재 표시한 기록만 선택한다. 다른 연도의 재독을 조용히 함께 바꾸지 않는다.
책 단위 관리 UI를 쓴다면 확인 단계에 `2권 · 독서 기록 4개`와 포함 회독을 명시해야 한다.
`이 책의 모든 회독을 비공개` 같은 확장은 별도의 명시적 선택으로 제공한다.

### 삭제는 연결 데이터까지 설명한다

현재 단건 삭제는 물리 삭제다. 책 행의 평점·리뷰·메모가 사라지며 FK CASCADE로 해당 개인 책 스레드의
댓글·좋아요·읽음 이력과 독서 활동 등도 함께 삭제된다. 해당 책을 가리키는 알림은 서버가 추가로 정리한다.
전역 책 정보·전역 댓글·다른 사용자의 독서 기록은 삭제 대상이 아니다.

확인창에 제목 일부, 선택 기록 수, 연결 기록도 삭제되고 복구할 수 없다는 설명을 표시한다.
비공개 변경은 기록을 보존한다는 점을 함께 안내한다.

## 서버 구현 경계

클라이언트에서 단건 API를 여러 번 호출하는 방식은 중간 실패로 일부만 처리될 수 있어 일괄 전용 API가 필요하다.

1. 알림은 선택 ID 모드와 읽은 알림 전체 모드를 구분하고 소유자는 세션으로 결정한다.
2. 책은 원본 독서 기록 ID와 명시적 연산(public/private/delete)만 받는다. 임의 PATCH 본문은 받지 않는다.
3. ID 형식·중복·최대 건수를 검사하고 선택 전체의 소유권을 확인한다. 타인 기록이 섞이면 전체를 거절한다.
4. 책 변경은 DB 트랜잭션으로 처리한다. 연결 알림 정리까지 포함할 수 있는 서버 전용 RPC를 검토한다.
5. 재전송 결과가 모호하지 않게 요청 ID 또는 처리 결과를 반환한다. 실제 처리 ID와 개수를 응답한다.
6. 알림 목록·드롭다운·읽지 않은 수·앱 배지를 함께 갱신한다. 책 변경 후 서재·비공개 목록·공유 이미지·공개 통계를 갱신한다.
7. 공개 통계는 현재도 공개 기록 기준이므로 비공개 변경 후 권수·배지·랭킹이 바뀔 수 있다.
8. 저장된 AI 취향 이력과 공유 이미지 캐시의 노출 범위도 점검한다. 비공개 변경이 과거 분석까지 자동 재생성한다고 안내하지 않는다.

알림은 기존 낙관적 캐시 유틸을 확장할 수 있다. 책 일괄 삭제는 서버 성공 후 목록과 통계를 갱신하는 방식이 단순하다.

## 구현 순서와 완료 기준

1. 알림 선택 삭제 + 읽은 알림 모두 삭제.
2. 서재 관리 + 선택 공개/비공개: 회독별 선택 단위와 복구 동선 확정.
3. 서재 선택 삭제: 트랜잭션·연결 데이터·확인창까지 포함.

필수 검증: 타인 기록 변경 거절, 불러오지 않은 읽은 알림까지 전체 삭제, 읽지 않은 알림 보존,
필터 변경 시 선택 초기화, 여러 연도·재독의 처리 범위, 공개/비공개 왕복, 연결 알림 정리,
실패 시 선택 유지·중복 클릭 방지, 모바일 내비게이션과 키보드 포커스 충돌 여부.

## 구현 및 검증

- 진입: 내 서재의 `서재 관리` → `/library/manage`. 비공개·완독·읽는 중·위시리스트와 회독별 원본 기록을 조회한다.
- 관리 조회는 소유자 전용이며 제목·저자, 독서 상태, 공개 범위, 등록 연도로 검색한다. 페이지당 50개, 페이지 변경 시 선택을 초기화한다.
- 알림은 `선택`으로 관리 모드에 들어가고, 더보기의 `읽은 알림 모두 삭제`는 불러오지 않은 페이지도 처리한다.
- API: `POST /api/notifications/bulk`, `POST /api/books/bulk`, `GET /api/books/manage`. 세션으로 소유권을 확인한다.
- DB: `20261027010000_bulk_management.sql`. `perform_bulk_action` RPC가 변경·연결 알림 정리·결과 영수증을 한 트랜잭션에 기록한다.
- 동일 요청 ID는 최초 결과를 재사용한다. 실패 시 다이얼로그와 선택을 유지하며 같은 ID로 재시도한다.
- 입력은 최대 500 ID로 제한한다. 읽은 알림 전체 삭제에는 ID 목록 대신 시각 경계를 사용한다.
- 공개 취향 이력 RPC는 현재 공개 책의 근거만 방문자에게 돌려준다. 과거 성향 이름·주제는 자동 재분석하지 않는다.
- 로컬 DB에 이 마이그레이션만 적용해 검증했다. 운영 배포에는 마이그레이션 적용이 필요하며 운영 DB는 변경하지 않았다.

PGlite에서 소유권·재독 범위·연결 삭제·중간 실패 롤백·재시도·페이지 밖 읽은 알림 삭제·권한/입력 제한을 검증했다.
실제 로컬 로그인 E2E로 선택 삭제, 읽지 않은 알림 보존, 공개/비공개 왕복, 필터 선택 초기화, 오류 후 재시도와 모바일 가로 넘침을 확인했다.
