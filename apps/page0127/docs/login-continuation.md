# 가입·책 담기 이어가기

## 바뀐 동작

- 맛보기 저장·독서 목표 저장·인생책 등록·공개 책 담기에서 로그인으로 갈 때 `shelf` 전달값을 붙인다.
- 전달값은 책 식별자·읽고 싶은 책 여부·목표·인생책 식별자·저장 시각만 포함한다. 계정, 메모, 평가,
  이미지 주소는 넣지 않는다.
- 다른 브라우저에서는 공개 도서 카탈로그에서 메타데이터를 복원한다. 검색으로 고른 새 책은 ISBN으로
  공급자에서 조회하며, 선택은 최대 20권·24시간으로 제한한다.
- 같은 브라우저에 일치하는 선택이 남아 있으면 그 원본을 우선해 재조회 실패로 선택을 잃지 않게 한다.
  다른 선택이거나 손상·만료된 링크는 대신 사용하지 않는다.
- 이미 로그인한 브라우저에서는 선택한 내용을 보여 주고 저장 버튼을 누른 뒤 이어 간다. 링크
  열기만으로 사용자 기록을 추가하지 않는다.
- 일반 ‘내 책장에 담기’는 읽고 싶은 책으로, ‘나도 읽었어요’는 완독으로 담는다. 읽고 싶은 책에는 완독
  연도를 묻지 않는다.
- 원래 목적지는 OAuth 콜백 → 최초 온보딩 → 완료 액션까지 전달한다. 외부 URL·인증 왕복 경로는 버린다.
  가입 완료 이벤트는 서재 외의 복귀 화면에서도 처리한다.

DB 마이그레이션이나 새 외부 서비스 설정은 없다. AI 평점 입력 화면을 추가하는 작업은 이 변경에
포함하지 않는다.

## 확인한 범위

- Node 22.19.0, lockfile 기준 의존성 설치.
- 단위 테스트 155개 파일·1,035개 통과. 전달값 만료·손상·식별자 검증, 부분 실패, 기존 선택 보존, 읽고
  싶은 책/완독 구분, 온보딩 목적지 보존 포함.
- 타입 검사와 변경 파일 lint 통과.
- 로컬 Docker의 공개 설정만 사용한 Playwright: 맛보기·책 상세 12개 통과, 1개 건너뜀(로컬 데이터에
  여러 책 묶음이 없음). 빈 브라우저 컨텍스트에서 목표·책 복원과 일반 담기의 상태·목적지 보존 확인.
- 운영 DB·유료 AI·실제 OAuth 공급자는 이 검증에서 사용하지 않았다.

## Preview 배포 뒤 실기기로 확인할 것

1. 인스타·카카오톡 안에서 책 두 권을 선택하고 저장 → 외부 브라우저로 열기 → 같은 선택이 안내되는지
   확인.
2. 구글 또는 카카오 신규 가입 → 나이 확인·아이디 설정 → 원래 책 화면 또는 본인 서재로 복귀 → 선택한
   책이 실제 저장됐는지 확인.
3. 외부 브라우저가 이미 로그인돼 있으면 저장 확인 화면이 먼저 나오고, 취소 시 책이 추가되지 않는지
   확인.
4. 일반 담기는 읽고 싶은 책으로, 나도 읽었어요는 완독으로 저장되는지 확인.
5. 선택 복원 실패·브라우저 저장소 차단 시 안내가 보이는지 확인. 실제 앱 전환과 OAuth 검증을 자동
   테스트 완료로 표시하지 않는다.
