# 직접 등록 도서와 공용 카탈로그 검수

## 사용자 흐름

- `/books/add`의 **직접 등록**에서 제목·저자, 선택적으로 출판사·ISBN13·출처 웹 주소를 입력한다.
- 이어서 기존 독서 기록 폼으로 완독 시점·평점·메모·공개 설정을 저장한다. ISBN이 없으면 내부 UUID
  식별자를 쓴다.
- 미승인 기록은 본인에게만 보인다. 직접 등록한 표지·책등 이미지는 받지 않고 기본 표지를 표시한다.
- `/books/requests`에서 대기·승인·보완 요청·반려와 운영자 사유를 확인한다. 승인 전 정보는 수정 후
  재제출할 수 있다.
- 승인되면 공용 목록·검색에서 찾을 수 있다. 개인 기록은 저장한 공개 설정을 따른다. 대기 중
  명시적으로 비공개로 바꾼 경우도 보존한다.
- 프로필 사진 업로드는 이번 작업과 무관하며 기존 방식을 유지한다.

## 운영자 흐름

- 관리자 메뉴 **도서 검수** → `/admin/books`.
- 상태별 필터, 제목·저자·ISBN 검색, 페이지당 20건. 오래된 요청부터 보여 준다.
- 실제 도서 존재·제목/저자·출판사/출처 일치·공용 목록 중복을 확인한다. 책 내용 전체를 보증하는
  검수는 아니다.
- 출처 링크, YES24 검색, 기존 공용 도서 검색으로 대조한다. 제출한 임의 URL은 서버가 가져오지 않는다.
- 승인 / 보완 요청 / 반려. 보완·반려 사유는 필수이며 등록자에게 표시된다.
- 처리 시점의 서지 정보 스냅샷·검수자·사유·시각을 감사 테이블에 남긴다. 요청 수정 또는 다른 관리자의
  처리가 먼저 일어나면 오래된 버전의 결정을 거절한다.
- 승인된 수동 도서를 다시 보완 요청·반려하면 해당 기록의 공용 노출도 닫힌다. 개인 독서 기록은
  삭제하지 않는다.

## DB 보안과 기존 데이터

`20261028000000_book_catalog_review.sql`이 필요하다.

- 기존 알라딘·YES24 카탈로그는 승인 상태로 보존한다. 기존 수동 카탈로그는 검수 대기로 전환하고 임의
  표지를 제거한다.
- 사용자가 직접 카탈로그를 INSERT하면 `source`/승인/검수자를 조작해도 강제로 수동·대기 상태가 된다.
- 새 공급자 도서는 서버가 공급자에서 직접 확인한 메타데이터로 등록한다. 브라우저가 주장하는
  `source`를 승인 근거로 사용하지 않는다.
- 개인 독서 기록의 서지 정보는 공용 카탈로그를 기준으로 정규화한다. 검증된 ISBN에 임의 제목·표지를
  덧씌우는 우회를 막는다.
- 미승인 공용 도서 SELECT는 제출자에게만 허용하고, 공용 페이지/API는 명시적으로 승인 상태만
  조회한다.
- 미승인 개인 기록의 공개 설정은 DB 트리거에서 차단한다. 책·활동에도 제한 RLS를 추가한다.
- 검수 RPC는 service_role만 실행 가능하다. 앱의 검수 액션은 매번 관리자 세션을 다시 확인하고
  검수자는 서버에서 결정한다.
- 검수 사유는 해당 카탈로그 제출자에게 표시된다. 같은 ISBN을 여러 사람이 기록하면 하나의 공용 검수
  상태를 공유한다.

## 적용과 검증

운영 DB에는 적용하지 않았다. 먼저 마이그레이션을 적용한 뒤 앱을 배포한다. 마이그레이션 이후 이전
버전 앱이 새로운 카탈로그를 만들면 수동·대기로 처리되므로 두 배포 간격은 짧게 유지한다.

로컬 SQL 테스트는 PGlite(PostgreSQL)에서 실제 마이그레이션·RLS·트리거·RPC를 실행한다. 출처 위조,
승인 우회, 타인/익명 조회, 활동 노출, 상태 전이, 공개 설정 보존, 재제출 충돌, RPC 권한과 감사 이력을
검증한다. 별도 단위 테스트로 서버 관리자 게이트, ISBN·출처 검증, 승인 도서 검색을 확인한다.

자동 이미지 검사·욕설 필터·프로필 신고·책 신고는 이 구현에 포함하지 않는다.
