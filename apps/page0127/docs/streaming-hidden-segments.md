# 본문이 두 벌 보이는 현상 (`<div hidden id="S:n">`)

> 조사일: 2026-10-15 · React 19.3.0-canary(Next 16.4 내장) · 운영 `page0127.com` 에서 재현
>
> **결론: 앱 버그가 아니다. 백그라운드 탭(가려진 브라우저 창)에서만 생기고, 탭을 보면 바로
> 사라진다.** 측정할 때만 조심하면 된다.

## 무엇이 보였나

비로그인으로 `/stronger_khj?year=2026` 를 연 뒤 DOM 을 보면 `<body>` 바로 아래에
`<div hidden id="S:1">` 이 남아 있고, 그 안에 본문이 **통째로 한 벌 더** 있었다. `h1` 2개,
`#visitor-signup-title` 2개, `[data-chemi-duo]` 2개. 홈 `/` 은 `S:*` 6개, `/about` 은 0개(스트리밍
경계가 없는 페이지).

## 원래 동작 — 스트리밍 SSR 이 본문을 끼워 넣는 순서

1. 서버가 먼저 스켈레톤(Suspense fallback)을 보낸다. 자리 표시는 `<!--$?--><template id="B:1">`.
2. 데이터가 준비되면 본문을 `<div hidden id="S:1">` 에 담아 뒤늦게 보낸다.
3. 같이 오는 `$RC("B:1","S:1")` 스크립트가 숨긴 본문을 자리로 옮기고 `S:1` 을 지운다.

React 19.2 부터 3번이 바뀌었다. 바로 옮기지 않고 **다음 화면 그리기(`requestAnimationFrame`) 때
묶어서** 옮긴다(`$RB` 대기열 → `$RV` 실행, 300ms 간격 조절). 대기 중인 경계는 `<!--$~-->` 로
표시된다.

## 왜 남았나 — 두 가지가 겹쳤다

**① 탭이 가려져 있으면 `requestAnimationFrame` 이 아예 안 돈다.** 브라우저가 안 보이는 탭의 화면
그리기를 멈추기 때문이다. 그래서 `$RV` 가 실행되지 않고 `S:1` 이 숨은 채 남는다. 조사 당시 측정
브라우저 창이 가려져 있었다.

**② 그 사이 React 가 본문을 직접 새로 그렸다.** 루트 레이아웃의 `CurrentUserProvider` 는
`/api/auth/me` 응답이 오면(`isLoading` true → false) 컨텍스트 값을 바꾼다. React 는 아직
하이드레이션 안 된 경계 안에 이 컨텍스트를 쓰는 컴포넌트가 있는지 알 수 없어서, 대기 중(`$~`)인
경계를 **서버 HTML 을 버리고 클라이언트에서 새로 그린다.** 이 새 사본이 `<main>` 에 보이고, 서버
사본은 ①때문에 `S:1` 에 숨은 채 남는다 → 두 벌.

## 증거 (운영에서 Playwright 로 측정)

| 조건                                 | 결과                                                                   |
| ------------------------------------ | ---------------------------------------------------------------------- |
| 보이는 탭, 빠른 망 ×3                | `S:*` 556~602ms 에 정리, `/auth/me` 응답은 그 뒤(745~1093ms). `h1` 1개 |
| 보이는 탭, 느린 망 + CPU 4배 감속 ×3 | `S:*` 642~3691ms 에 정리, `/auth/me` 는 8~9초. `h1` 1개                |
| rAF 정지(백그라운드 흉내)            | `S:*` 3개 남음, `h1` 2개 — 운영 관찰과 같다                            |
| rAF 정지 + `/auth/me` 보류           | 경계는 `$~` 그대로, `<main>` 은 스켈레톤, `h1` 1개(숨은 쪽)            |
| 위에서 `/auth/me` 만 풀어줌          | B:1·B:2 가 클라이언트 렌더로 교체, `h1` 2개                            |
| 위에서 rAF 를 다시 돌림              | `S:*` 즉시 정리, `h1` 1개                                              |

홈도 같았다(경계 5개가 `/auth/me` 직후 클라이언트 렌더로 교체). 하이드레이션 불일치 에러· 콘솔
에러는 어느 경우에도 없었다.

보이는 탭에서 ②가 안 생기는 이유: `/auth/me` 는 하이드레이션이 끝난 뒤에야 요청되는데, 하이드레이션
JS 는 HTML 스트림 뒤에 실행되므로 그 전에 이미 `$RV` 가 돌아 있다.

## 사용자 영향

- **보이는 탭: 없음.** 위 표대로 항상 정상 하이드레이션된다.
- **백그라운드로 연 탭(Ctrl+클릭 등)**: 탭을 보기 전까지 DOM 이 두 벌이고, 본문을 하이드레이션 대신
  새로 그리느라 CPU 를 조금 더 쓴다. 탭을 여는 순간 rAF 가 돌아 숨은 사본이 지워진다. 아무도 보지
  않는 동안의 일이라 고치지 않았다.

고치려면 ②를 없애면 된다 — 컨텍스트 대신 각 컴포넌트가 `useCurrentUser()`(React Query 구독)를 직접
부르게 하면 로그인 상태가 바뀌어도 컨텍스트 전파가 없다. 다만 소비처 6곳을 바꿔야 하고, 그래도
①(숨은 `S:*`)은 React 설계상 그대로 남는다.

## 측정할 때 주의

- **DOM 감사·접근성 검사는 탭이 보이는 상태에서 한다.** 가려진 창·백그라운드 탭에서 재면 `S:*` 사본
  때문에 `id` 중복, `h1` 2개 같은 가짜 문제가 잡힌다.
- 확인법: `document.visibilityState === 'visible'` 이고 `div[hidden][id^="S:"]` 가 0개인지 본다.
- 재현 스크립트는 `window.requestAnimationFrame` 을 콜백을 쌓기만 하는 함수로 바꿔 백그라운드 탭을
  흉내 냈다(헤드리스 Chrome 은 탭이 늘 보이는 상태라 그냥은 재현이 안 된다).
