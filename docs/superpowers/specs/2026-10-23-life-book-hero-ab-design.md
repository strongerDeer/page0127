# 홈 히어로 A/B — "당신의 인생책은?" 설계

> 2026-10-23 · 대화로 정한 방향을 구현 단위로 옮긴다. 배포는 10/26 기준선 측정 뒤
> (`00_docs/00_남은_작업_목록.md` 가입 유도 원칙 ②). 개발은 지금 한다.

## 1. 왜 하나

**목적은 어드민에서 "처음 온 사람이 실제로 가입까지 오는지"를 단계별로 보는 것이다.** 지금 맛보기
흐름은 그걸 볼 수 없다 — 저장 버튼 다음 단계에 이벤트가 비어 있다(7절).

그 위에서 질문 하나를 비교한다. 맛보기 히어로(10/8)는 "이 중에 읽은 책이 있나요?"로 **여러 권을
고르게** 한다. B 는 "당신의 인생책은?"으로 **한 권을 검색해서 찾게** 한다. 떠오르는 한 권이 있는
사람에게는 목록에서 고르는 것보다 바로 찾는 편이 빠르고, 그 한 권이 서재 첫인상(틸 테두리)이 된다는
가설이다.

가설이라 **바꾸지 않고 나눠 본다.** 방문자가 적어 전후 비교로는 기간 효과와 섞이므로, 지금 화면(A)을
대조군으로 같은 기간에 함께 돌린다.

**성공 기준**

- 처음 온 비로그인 방문자가 50:50 으로 A/B 중 하나를 받고, 다시 와도 같은 쪽을 본다.
- B 에서 찾은 한 권은 로그인 뒤 서재에 **인생책**(평점 5 + `is_life_book`)으로, 완독일 "모름"으로
  담긴다. 지어낸 날짜가 들어가지 않는다.
- 어드민에서 `봤다 → 골랐다 → 저장 → 로그인 시도 → 가입 → 서재에 담김`을 A/B 로 나눠 본다.
- 스위치를 끄면 모두 A 를 본다(배포해 두고 10/26 뒤에 켠다).

## 2. 범위

**한다**: 그룹 배정(쿠키), 켜고 끄는 스위치, B 화면(검색 한 권), 인생책 보관과 담기, **빠진 퍼널
이벤트 채우기**, GA 사용자 속성, 어드민 A/B 깔때기.

**하지 않는다**

- 투표·인원 수 표시("N명이 골랐어요", "등록하면 N명이 돼요" 등) — 뺐다(2026-10-23).
- 시점 안내 문구("언제 읽었는지 몰라도 괜찮아요") — 등록해 보기 전에는 의미가 없다.
- 공개 서재 인생책 카드(히어로 실험이 끝난 뒤 — 원칙 ③).
- h1 변경("책장을 보면, 그 사람이 보인다."는 두 쪽 모두 같다 — 검색 노출 문장을 흔들지 않는다).
- 맛보기 단계의 별점 입력, 로그인 사용자 홈 변경, "나도 읽었어요"(책 상세) 흐름 변경.

## 3. 배정과 스위치

| 항목      | 정한 것                                                                           |
| --------- | --------------------------------------------------------------------------------- |
| 쿠키      | `hero_variant` = `a` \| `b`, 90일, `SameSite=Lax`, **httpOnly 아님**(7절 참고)    |
| 배정 시점 | `proxy.ts` — 쿠키가 없고, 로그인한 적 없고(인증 쿠키 없음), 경로가 `/` 일 때만    |
| 비율      | 50:50 (`Math.random() < 0.5`)                                                     |
| 스위치    | 서버 환경 변수 `HERO_AB=on`. 그 밖의 값이면 배정하지 않고 모두 A                  |
| 렌더      | 홈 서버 컴포넌트가 쿠키를 읽어 A 면 `ShelfPreview`, B 면 `LifeBookHero` 를 그린다 |

- **클라이언트 랜덤을 쓰지 않는 이유**: 서버가 그린 화면이 깜빡이며 바뀌고(하이드레이션 불일치),
  새로고침마다 그룹이 바뀌어 측정이 안 된다.
- **같은 요청에서 보이게**: 응답 쿠키만 심으면 그 요청의 서버 컴포넌트는 쿠키를 못 본다.
  `updateSession` 전에 `request.cookies.set` 으로 요청에도 넣는다.
- **스위치를 끄면** 이미 받은 쿠키가 남아 있어도 A 로 그리고(쿠키보다 스위치가 먼저), proxy 가 다음
  요청에서 그룹 쿠키를 지운다 — 그래야 GA 사용자 속성도 더 이상 보내지 않는다.
- **로그인 여부는 인증 쿠키 이름으로 본다**(`sb-<ref>-auth-token`, 나뉜 `.0`·`.1` 포함). 그룹은 세션
  확인(`getUser`) 전에 정해야 같은 요청에 반영되기 때문이다. 이 브라우저에서 로그인한 적 있는 사람은
  빠지는데, 실험 대상이 "처음 온 사람"이라 오히려 맞다.
- 경로를 `/` 로 좁힌 이유: 공개 서재·책 상세로 들어온 사람은 홈에 올 때 배정된다. 모든 경로에서
  배정하면 홈을 보지도 않은 사람이 그룹 수에 섞인다.

## 4. B 화면 — `LifeBookHero`

A(`ShelfPreview`)는 건드리지 않는다. B 는 같은 자리(비로그인 홈 최상단)에 들어가는 **새 컴포넌트**다.
둘이 섞이면 A 가 조금이라도 바뀌어 대조군이 흔들린다.

```
┌──────────────────────────────────────────────────────────────┐
│  책장을 보면,                        리더들이 뽑은 인생책이에요  │
│  그 사람이 보인다.                   ┌──┐┌──┐┌──┐┌──┐┌──┐       │
│                                      └──┘└──┘└──┘└──┘└──┘       │
│         당신의 인생책은?                                         │
│         ┌ ─ ─ ─ ─ ┐                                            │
│           실루엣      [🔍 책 제목이나 저자로 찾아보세요     ]   │
│         │  (크게)  │                                           │
│         └ ─ ─ ─ ─ ┘                                            │
└──────────────────────────────────────────────────────────────┘
                     ↓ 검색해서 한 권을 찾으면
┌──────────────────────────────────────────────────────────────┐
│         당신의 인생책은?                                         │
│         ┌─────────┐  『대온실 수리 보고서』                     │
│         │  표지   │  김금희                                     │
│         │  (크게) │  [ 내 서재에 등록하기 → ]   다른 책 찾기     │
│         └─────────┘  무료 · 구글·카카오로 10초 가입              │
└──────────────────────────────────────────────────────────────┘
```

| 자리                         | 정한 것                                                                                       |
| ---------------------------- | --------------------------------------------------------------------------------------------- |
| h1                           | A 와 같다                                                                                     |
| 소개 문장                    | **없다** — 질문이 곧 소개다                                                                   |
| 질문                         | **"당신의 인생책은?"** — 화면에서 가장 큰 글자(h1 다음 단계, h2)                              |
| 실루엣                       | 2:3 비율의 빈 표지 자리(점선 테두리, 틸 계열). 데스크톱 약 200px 폭으로 크게                  |
| 검색                         | `ShelfSearch` 재사용, 자리표시 문구 "책 제목이나 저자로 찾아보세요"                           |
| 찾은 뒤                      | 실루엣 자리에 표지 + 틸 테두리 + 👑, 옆에 제목·저자, **[내 서재에 등록하기]**, "다른 책 찾기" |
| 리더들이 뽑은 인생책         | 표지 5권 **보여주기만**(누르는 대상 아님, 인원 수 없음). 5절 규칙                             |
| A 의 0권 목표(`GoalStarter`) | 넣지 않는다 — B 는 한 가지 행동만 둔다                                                        |

- **한 권만** 고른다. 다른 책을 찾으면 바꾼다. "다른 책 찾기"는 찾은 책을 비우고 검색으로 돌아간다.
- 버튼 아래 "무료 · 구글·카카오로 10초 가입"은 A 와 같은 문구다(두 쪽의 차이를 질문 하나로 좁힌다).
- 다시 온 방문자: 보관분에 인생책이 있으면 찾은 상태로 되살린다.
- 접근성: 실루엣은 장식(`aria-hidden`), 찾은 표지의 이름은 `"{제목} (내 인생책)"`. 상태 변화는
  `aria-live` 로 알린다("『…』을 인생책으로 골랐어요").

## 5. "리더들이 뽑은 인생책" 5권

- 출처: 홈 하단 랭킹과 같은 `get_book_ranking_with_delta('best', 5)` — **공개 서재**의 인생책만 센다.
- **실제 데이터만 쓴다.** 운영자가 고른 책으로 채우지 않는다("리더들이 뽑은"이 사실이어야 한다).
- **3권 미만이면 이 줄을 숨긴다** — 실루엣과 검색만 남는다.
- 인원 수·순위·증감은 표시하지 않는다(투표 기능을 뺐다).
- 캐시: `unstable_cache` 1시간(맛보기 10권과 같은 방식). 실패하면 줄을 숨긴다 — 히어로 전체를 막지 않는다.

## 6. 보관과 담기

**보관(localStorage `page0127:pending-shelf`)** — `v: 1` 을 유지하고 선택 필드를 더한다.

```ts
type PendingShelf = {
  v: 1;
  savedAt: number;
  books: PendingBook[];
  goal: PendingGoal | null;
  /** B 에서 찾은 인생책. books 안에 있는 isbn 이어야 한다 */
  lifeBookIsbn?: string | null;
};
```

- B 의 저장: `books = [찾은 책]`, `lifeBookIsbn = 그 isbn`. 이미 보관분이 있으면(예: 책 상세의
  "나도 읽었어요") 그 책들은 두고 인생책을 앞에 더한다.
- 버전을 올리지 않는 이유: 배포 순간 남아 있는 보관분(24시간)이 전부 깨진다. 필드가 없으면 null 로 읽는다.
- 검증: 문자열이 아니거나 `books` 에 없는 isbn 이면 **null 로 버린다**(보관분 전체를 버리지 않는다).

**담기(`PendingShelfClaimer` → `toBookInput`)** — 인생책 한 권만 다르게 담는다.

| 필드                                | 인생책        | 나머지 (지금과 같음) |
| ----------------------------------- | ------------- | -------------------- |
| `status`                            | `completed`   | `completed`          |
| `rating`                            | **5**         | 없음                 |
| `is_life_book`                      | **true**      | 없음                 |
| `completed_date` / `completed_year` | 비움 → "모름" | 비움 → "모름"        |

- 평점 5 + 플래그는 등록 폼과 같은 규칙이다(인생책은 최고점의 별칭 — `BookRegistrationForm`).
- 이미 서재에 같은 책이 있으면 지금처럼 건너뛴다(인생책 표시도 덮지 않는다).
- 로그인 화면 안내(`loginNotice`)는 바꾸지 않는다 — 권수만 말한다.

## 7. 측정 — 빠진 퍼널 이벤트 채우기

**지금 비어 있는 곳 (2026-10-23 확인)**

| 단계                 | 지금                                                                                         |
| -------------------- | -------------------------------------------------------------------------------------------- |
| 히어로를 봤다        | 이벤트 없음 → 분모가 없다                                                                    |
| 저장 → 로그인 화면   | `signup_start` 는 랜딩의 시작하기 버튼(`StartCtaButton`)에서만 나간다. 맛보기 길에선 안 나감 |
| 로그인 화면에서 시도 | 이벤트 없음 — 로그인 화면에서 떠났는지 알 수 없다                                            |
| 서재에 담김          | `book_add` 는 `/books/add` 에서만 나간다. 로그인 뒤 담기(`PendingShelfClaimer`)에선 안 나감  |

**A/B 공통 퍼널 (이 순서로 어드민에 그린다)**

| #   | 이벤트                | 시점                                      | 파라미터                             | 비고   |
| --- | --------------------- | ----------------------------------------- | ------------------------------------ | ------ |
| 1   | `shelf_preview_view`  | 히어로가 화면에 보였다(한 번)             | —                                    | **새** |
| 2   | `shelf_preview_pick`  | A: 책을 골랐다 / B: 찾아서 한 권을 정했다 | `source`, `count`, B 는 `life: true` | 기존   |
| 3   | `shelf_preview_save`  | A: 저장 / B: 내 서재에 등록하기           | `count`, B 는 `life: true`           | 기존   |
| 4   | `login_start`         | 로그인 화면에서 구글·카카오 버튼을 눌렀다 | `method`                             | **새** |
| 5   | `sign_up`             | 가입 완료(온보딩 끝)                      | `method`                             | 기존   |
| 6   | `shelf_preview_claim` | 로그인 뒤 보관분이 서재에 담겼다          | `added`, `failed`, `life_book`       | **새** |

- 기존 회원이 로그인하면 5 없이 4 → 6 으로 간다. 어드민 표는 5 를 "신규만"으로 표시한다.
- `login_start` 는 맛보기를 거치지 않은 로그인에서도 나간다. 어드민은 사용자 속성으로 나누므로
  A/B 그룹 밖(배정 안 된 사람)은 표에 들어오지 않는다.
- B 의 검색 입력 자체는 1차에 세지 않는다(`ShelfSearch` 는 A 도 쓰므로 A 를 바꾸지 않으려고).

**그룹은 사용자 속성으로 남긴다**

- `trackEvent` 가 **그 페이지의 첫 이벤트를 보내기 직전에** 쿠키를 읽어
  `gtag('set', 'user_properties', { hero_variant })` 를 한 번 부른다.
- 레이아웃에 따로 컴포넌트(`HeroVariantTracker`)를 두는 안은 버렸다(구현 중 바꿈): React 는 자식
  effect 를 부모보다 먼저 돌려서, 페이지 안의 `shelf_preview_view` 가 그룹 없이 먼저 나간다.
- 이유: 4~6 이 홈이 아닌 로그인·온보딩·서재에서 난다. 쿠키가 httpOnly 가 아닌 이유도 이것이다.
- 쿠키가 없으면 보내지 않는다(스위치를 끄면 proxy 가 쿠키를 지우므로 함께 멈춘다).

**⚠️ 배포 전에 GA 에 등록한다 (원칙 ④)**

- 사용자 범위 맞춤 측정기준: 이름 `히어로 실험`, 사용자 속성 `hero_variant`

## 8. 어드민

유입분석에 **"히어로 A/B" 카드**를 더한다. 기존 요청과 묶지 않고 따로 보낸다 —
`customUser:hero_variant` 가 등록되기 전에는 GA 가 400 을 주므로(`toCtaLocationRequest` 와 같은 이유).

```ts
dimensions: [{ name: "eventName" }, { name: "customUser:hero_variant" }];
metrics: [{ name: "totalUsers" }];
```

- 표: 7절의 6단계(행) × A·B(열). 각 칸에 사용자 수와 1단계(봤다) 대비 비율.
- 앞 기간 비교는 넣지 않는다(실험은 같은 기간 안에서 비교한다).
- 한쪽 1단계가 30명 미만이면 "아직 판단하기 이르다" 문구를 함께 보인다.
- 측정기준이 등록되지 않아 400 이면 등록 안내 문구를 보인다(`location` 과 같은 방식).
