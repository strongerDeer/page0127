# 리더 탐색 — 설계

> 2026-10-06 · 진행 모드: 자율 진행(사용자 선택). 커밋·푸시는 사용자 요청 시에만.

## 1. 문제

ID(닉네임·사용자명)를 모르면 다른 리더를 만날 길이 없다.

- `/search`(사용자 검색)는 **검색어를 넣어야만** 결과가 나오고, 첫 화면은 빈 안내 상자다.
- 책 상세의 `ReaderProfiles`("이 책을 완독한 사람들")는 겹친 아바타 10개뿐이다.
  - 이름은 `title` 툴팁으로만 보여 **모바일에서는 누군지 알 수 없다.**
  - **완독자만** 보여서 읽는 중인 리더가 빠진다.
  - 넘치면 나오는 `+`는 누를 수 없는 막다른 표시다.

## 2. 사용자 결정

- 입구: **책을 통해 만나기** (책 상세에서 그 책을 읽은 리더로)
- **제작자 `stronger_khj`는 추천에 뜨게 한다** (사용자 입력 "stronge_khj"는 운영 사용자명
  `stronger_khj`(packages/quality/src/config.ts)의 오타로 판단)
- 보류: 취향 기반 추천(궁합), 뱃지·인플루언서

## 3. 설계

### ① 책 상세 — "이 책을 읽은 리더"

- 대상: `books.isbn = 이 책` · `is_public = true` · `status ∈ {reading, completed}`
  (`want_to_read`는 "읽은" 리더가 아니므로 제외)
- 한 사람이 재독으로 여러 행을 가질 수 있다 → 사람 단위로 합치고 **완독이 읽는 중보다 우선**.
- 순서: 최근 기록(`updated_at` 내림차순) 순.
- 표시: 행 목록 — 아바타 · **이름(텍스트로 항상 보임)** · 상태 칩(완독 / 읽는 중).
  처음 5명, 나머지는 `<details>` "N명 더 보기"(최대 20명).
- 0명이면 지금처럼 블록 자체를 그리지 않는다.
- 블록 끝에 "다른 리더 둘러보기 →" 링크(`/search`).

순수 함수 `pickBookReaders(rows, max)` → `{ readers: {userId, status}[], total }`.

### ② 추천 리더 데이터

- `FEATURED_READER_USERNAME = 'stronger_khj'` (shared/config). 이 사람은 **항상 맨 앞**,
  카드에 "page0127. 제작자" 표시.
- 그 뒤는 **최근 공개 기록을 남긴 리더**: 공개 책 최근 80행(`updated_at` 내림차순)의 user_id를
  등장 순서대로 중복 제거.
- 로그인한 본인은 뺀다. 최대 8명.
- 각 리더의 최근 공개 표지 최대 3개를 같은 조회 결과에서 모아 카드에 붙인다
  ("책을 통해 만나기"와 같은 결 — 사람을 책으로 소개한다). 제작자는 최근 80행에 없을 수
  있으므로 제작자 표지는 **항상** 따로 조회한다(최근 9행 — 재독 중복을 감안).
- 표지는 `toRenderableSrc`와 같은 기준(그릴 수 있는 호스트만)으로 거른다.
- 조회 실패는 `console.warn` 후 빈 목록 → 화면은 기존 빈 상태로 떨어진다(검색은 그대로 동작).

순수 함수 `orderRecommended({ recentRows, featuredId, featuredRows, excludeId, limit })`.
`toRenderableSrc`는 소개 페이지 전용(`widgets/about/model`)에서 `shared/lib/imageHost`로 옮긴다
(features 가 widgets 를 import 할 수 없다 — FSD).

### ③ `/search` 첫 화면

- 검색어가 없을 때 빈 상자 대신 **"추천 리더"** 카드 그리드(서버 컴포넌트)를 보여준다.
  `UserSearch`에 `emptyState?: React.ReactNode` 슬롯을 더해 서버에서 그린 것을 넘긴다.
- 페이지 제목·설명: "리더 찾기" / "닉네임으로 찾거나, 최근 기록한 리더를 둘러보세요".
- 카드 = 프로필 링크(`ProfileLink`). 팔로우 버튼은 넣지 않는다(프로필에서 한다 — YAGNI).
- 메뉴 이름도 맞춘다: 데스크탑 GNB "사용자 검색" → "리더 찾기", 모바일 탭 "검색"(돋보기) →
  "리더 찾기"(사람 아이콘). 모바일 헤더의 돋보기는 책 검색이라 같은 아이콘이 두 뜻이었다.

## 4. 범위 밖

- DB 마이그레이션 없음 (기존 RLS·컬럼만 사용, `is_public` 명시 — RLS 집계 불변식)
- 비로그인용 공개 리더 목록 페이지, 취향 추천, 무한 스크롤

## 5. 검증

- vitest: `pickBookReaders`, `orderRecommended`
- e2e 는 추가하지 않는다: `/search`는 로그인 영역이라 CI e2e(비로그인)로 못 들어가고, 책 상세
  리더 블록은 DB 에 공개 기록이 있어야만 보여 CI 데이터에 기대게 된다.
- 대신 로컬에서 세션을 발급해 `/search`·책 상세를 데스크탑·모바일로 캡처 확인한다.
  로컬 DB 에는 `stronger_khj`가 없어 제작자 카드는 단위 테스트로만 확인된다 → 운영 배포 후 확인.
