# 홈 '책장 맛보기' 설계

> 2026-10-08 · 대화로 확정한 방향을 구현 단위로 옮긴다. 진행 방식: 자율(커밋·푸시는 사용자 전용).

## 1. 왜 하나

가입자가 사실상 없다. 홈은 "설명하지 않고 보여주는" 포털(배너·랭킹·인생책)인데, 보여 줄
데이터가 제작자 한 사람의 책장뿐이라 처음 온 사람에게 **가입할 이유**를 주지 못한다.
소개 페이지(`/about`)는 설득을 잘하지만 들어오는 길이 푸터와 홈 맨 아래 링크뿐이다.

둘 다 빠진 것: 이 서비스의 보상("내 책장이 나를 말해 준다")을 **가입 전에 겪어 볼 수 없다.**
→ 홈 첫 화면에서 읽은 책을 고르면 **내 책장**이 그려지고, 저장하려면 가입한다.
가입은 "부탁"이 아니라 "이미 만든 것을 지키는 행동"이 된다.

**성공 기준**

- 비로그인 방문자가 첫 화면에서 클릭 한 번으로 내 책장에 책이 꽂히는 것을 본다.
- 0권인 사람도 막다른 길 없이 다음 행동(목표 설정)이 있다.
- 로그인(+온보딩)을 마치면 고른 책·목표가 **그대로** 서재에 들어가 있다. 빈 서재로 시작하지 않는다.
- 어디서 이탈하는지 GA 로 보인다.

## 2. 범위

**한다**: 홈 최상단 맛보기 섹션(비로그인만), 직접 고른 10권 + 다른 책 찾기(검색), 0권 목표 흐름,
로그인 후 서재에 담기, GA 이벤트 3개.

**하지 않는다**: 비로그인 AI 취향 분석(비용·남용), 맛보기 단계의 별점 입력(진입 부담),
판단형 문구("~쪽으로 기울어 있다" — 사용자 반려), 로그인 사용자 홈 변경, `/about` 변경.

## 3. 화면

```
읽은 책을 골라 보세요.                       ← 표지 그리드 10권, 탭하면 선택/해제 (aria-pressed)
[목록에 없나요? 다른 책 찾기]                ← 펼치면 검색창. 결과를 고르면 같은 책장에 추가
─ 내 책장 ─                                 ← 고른 순서대로 책등이 꽂힌다 (GrowingShelf 재사용)
1~4권  "2권만 더 모이면 취향 노트를 받아 볼 수 있어요."
5권~   "별점만 매기면 바로 취향 노트를 받아 볼 수 있어요."
[책장 저장하기]  → 로그인

0권    "아직 없어도 괜찮아요. 오늘부터 시작해요."
       올해 목표 [ − 12권 + ]
[목표 저장하기]  → 로그인
```

- 위치: `app/(public)/page.tsx` 의 `<h1 sr-only>` 바로 아래, 히어로 배너 위. **`!user` 일 때만** 렌더.
  로그인 사용자에게 "읽은 책을 골라 보세요"는 맞지 않는다.
- 0권/1권 이상 분기는 같은 섹션 안에서 바뀐다(페이지 이동 없음).
- 책장에 꽂힌 책을 다시 누르면 빠진다. 최대 20권(넘으면 버튼 비활성 + 안내).

### 안내 문구 (진행형)

취향 분석 조건은 **완독 + 별점** 5권이다 (`app/api/taste-analysis/analyze/route.ts`).
고르기만 한 책에는 별점이 없으므로 "n권 더 꽂으면 받는다"는 거짓이 된다 → 두 문장으로 나눈다.

| 고른 수 | 문구                                                 |
| ------- | ---------------------------------------------------- |
| 1~4     | `{5-n}권만 더 모이면 취향 노트를 받아 볼 수 있어요.` |
| 5+      | `별점만 매기면 바로 취향 노트를 받아 볼 수 있어요.`  |

순수 함수 `toShelfPreviewMessage(count)` 로 두고 테스트한다. 기준 5 는 상수로 공유한다
(분석 라우트의 매직 넘버 `5` 를 같은 상수로 바꾼다).

## 5. 로그인 너머로 넘기기

### 왜 `localStorage` 인가

- `next` 쿼리: 신규 가입자는 `toPostLoginPath` 가 **온보딩을 먼저** 보내므로 중간에 사라진다.
- 쿠키: 검색으로 고른 책은 메타데이터(제목·저자·표지·책등·설명…)를 통째로 들고 가야 해서 4KB 를 넘는다.
- `localStorage`: 온보딩을 거쳐도 남고, 크기 걱정이 없다. 카카오 앱 로그인 등으로 **다른 브라우저**에서
  돌아오면 사라진다 — 이 경우 조용히 빈 서재로 시작한다(실패를 알리지 않는다. 사용자는 잃은 줄 모른다).

### 형식

```ts
// key: 'page0127:pending-shelf'
type PendingShelf = {
  v: 1;
  savedAt: number; // ms. 24시간 지나면 버린다
  books: PendingBook[]; // 최대 20
  goal: { year: number; target: number } | null;
};
type PendingBook = {
  // POST /api/books 본문에 필요한 필드만
  isbn: string;
  provider_item_id: string | null;
  title: string;
  author: string | null;
  publisher: string | null;
  cover_image: string | null;
  spine_image: string | null;
  pub_date: string | null;
  category: string | null;
  source: string | null;
};
```

- 읽기는 `unknown` → 타입 가드 `parsePendingShelf`. 형식이 틀리거나 만료면 지우고 `null`.
- 쓰기·읽기·지우기 모두 try/catch(사파리 비공개 모드 등에서 던진다) — 실패해도 화면은 정상 동작.

### 로그인 후 담기 — `PendingShelfClaimer`

- 공통 레이아웃 `AppShell`(`(public)`·`(protected)` 둘 다 씀)에 마운트하는 클라이언트 컴포넌트.
  화면에 아무것도 그리지 않는다. **로그인 사용자일 때만** 실행한다 — 로그인 직후 도착지 `/{username}` 은
  `(public)` 그룹이다.
- 온보딩(`(onboarding)` 그룹)은 AppShell 밖이라 거기서는 자연히 실행되지 않는다 — 아이디가 정해진 뒤
  서재에서 담겨야 활동 기록이 맞는 주소로 남는다.
- 순서: 읽기 → **먼저 지운다**(새로고침·탭 두 개로 두 번 담기는 것을 막는다) → 책마다
  `GET /api/books?isbn&providerItemId` 로 중복 확인 → 없으면 `POST /api/books`
  (`status: 'completed'`) → 목표가 있고 `profiles.reading_goal` 이 비어 있으면 저장 → 토스트
  `"3권을 서재에 꽂았어요"` → `router.refresh()`.
- 일부 실패: 성공한 수만 알린다. 실패분은 다시 시도하지 않는다(이미 지웠다).
- 피드 활동: 책마다 `book_completed` 가 생긴다. 신규 가입자라 팔로워가 없어 소음이 없다(사용자 승인).
- 보안: 보관분은 사용자가 조작할 수 있지만 **본인 서재에 본인 권한으로** 기존 API 를 부르는 것뿐이다.
  새 권한이 생기지 않는다. 20권 상한·형식 검사로 대량 호출만 막는다.

### 목표 저장

- 기존 `updateReadingGoalAction` 은 `useActionState`(FormData) 전용이고 무조건 덮어쓴다.
  → 전용 서버 액션 `claimReadingGoalAction(goal)` 을 새로 둔다. 같은 검증(1~1,000권)을 하고,
  **비어 있을 때만** 넣는다.
- "비어 있다"의 정의: `reading_goal` 이 `null`, **`'{}'`(컬럼 기본값)**, `target` 이 없음, 또는
  `year` 가 올해가 아님. 이미 올해 목표가 있는 기존 사용자의 값은 덮지 않는다.
  판단은 순수 함수 `shouldClaimGoal(current, year)` 로 두고 테스트한다.

## 10. 확정된 결정 (2026-10-08)

1. 맛보기 문구는 **진행형**. 판단형("기울어 있다")은 쓰지 않는다.
2. 책 목록은 **직접 고른 10권 + 검색**. 랭킹 데이터가 쌓이면 전환한다.
3. 1권 이상 → 책장 저장, 0권 → 목표 설정. 둘 다 로그인으로 이어진다.
4. 비로그인 홈에만 노출한다. 로그인 사용자 홈은 그대로.
5. 고른 책마다 피드 활동이 생기는 것은 그대로 둔다. 대부분은 팔로워가 없는 신규 가입자다.
   **예외**: 로그아웃한 기존 사용자가 맛보기로 저장하면 팔로워 피드에 최대 20건이 생긴다 — 가입자가
   적은 지금은 드물어 그대로 둔다(2026-10-08 리뷰). 기존 사용자 유입이 보이면 클레이머를 최근 온보딩
   사용자로 제한하거나 담기 전에 확인을 묻는다.
6. 10/4 소개 페이지 설계의 "체험 데모 하지 않는다"는 **가짜 서재 조작**을 뺀 것이다. 이번은 방문자의
   실제 첫 기록이라 충돌하지 않는다.

## 11. 2차 — 비로그인 히어로로 (2026-10-08, 운영 확인 후)

운영 첫 버전은 "설정 화면 같은 흰 카드"였고 서비스 정체를 말하지 않았다. 시안(캔버스) 비교 후 A안으로 확정.

- **히어로화**: 비로그인 홈 맨 위. 제목 "책장을 보면, 그 사람이 보인다."(화면에 보이는 h1), 부제
  "읽은 책을 골라 책장을 채워주세요. 당신의 취향은 어떤가요?". 데스크톱은 왼쪽(문장·책장·버튼) · 오른쪽(고르기),
  모바일은 문장 → 고르기 → 책장. 바탕은 `tint-cool`, 흰 박스 없음.
- **24권 = 8권 × 3묶음**: [다른 책 보기 ↻ n/3]로 넘긴다. 고른 책은 묶음을 넘겨도 남는다. 표지 가장자리 밝기
  225 이상(흰 표지·YES24 흰 여백)은 뺐다 — 연한 바탕에서 칸이 비어 보인다.
- **저장 버튼은 고른 뒤에만** 나타난다("지금 책 저장하기"). 데스크톱은 그 자리를 미리 비워 둔다.
- **0권 흐름은 링크 한 줄**("아직 읽은 책이 없나요? 올해 목표부터 같이 세워봐요!"), 누르면 스테퍼.
- **다른 책 찾아보기**는 그리드 아래 버튼.
- **다시 온 방문자**: 24시간 보관분이 있으면 책장을 되살린다(`restoreSelection`).
- **롤링 배너는 로그인 사용자에게만**. 비로그인은 맛보기가 히어로를 맡는다.
