# 소개 페이지(/about) 리뉴얼 설계

> 2026-10-04 · 시안 v1~v7을 거쳐 사용자와 확정한 방향을 구현 가능한 단위로 옮긴다.
> 확정 시안: [assets/2026-10-04-about-mockup-v7.html](assets/2026-10-04-about-mockup-v7.html) — 브라우저로 열어 볼 것

## 1. 왜 바꾸나

지금 `/about`은 글만 있는 73줄짜리 문서 페이지이고, 들어오는 길도 푸터·sitemap 두 곳뿐이다.
가입 전 방문자는 "이게 뭔데 왜 써야 하지"에 답을 못 얻고, 가입한 사람은 무엇부터 할지 모른다.
첫 사용 가이드(코치 팁, PR #153)가 가입 **후** 현장 안내를 맡으므로, 소개 페이지는
**가입 전 설득을 위에, 이용 방법을 아래에** 둔다(사용자 결정 c).

**성공 기준**
- 처음 온 사람이 첫 화면에서 "읽은 책을 꽂아 두는 서비스"라는 것을 안다.
- 스크롤만으로 이용 순서(기록 → 목표 → 취향 분석)를 이해한다. 가로 스크롤은 없다.
- 페이지 끝에서 바로 카카오/구글로 가입할 수 있다.

## 2. 범위

**한다**: `/about` 페이지 재구성(7개 섹션), 랜딩 하단에 "어떻게 쓰나요?" 링크 추가.

**하지 않는다**: 체험 데모(가짜 서재 조작), 영상·로티, 캡처 이미지, 다크 전용 디자인,
앱 전체의 브랜드 표기(`page0127.`) 일괄 전환(결정 2).

## 3. 섹션 설계

공통 머리 형식(애플 문법): **파란 라벨 → 큰 제목(마침표로 끝남) → 회색 문단**, 모두 가운데 정렬.
예외는 없다 — 왼쪽 정렬은 이유가 있을 때만 쓴다.

| # | 섹션 | 내용 | 데이터 출처 |
|---|---|---|---|
| 1 | 히어로 | 라벨 "독서 기록 서비스, page0127." · 제목 "책장을 보면 그 사람의 (취향이/계절이/마음이) 보인다" · CTA 2개 · **파란 무대에 최근 표지 두 줄이 반대 방향으로 흐름** · "방금 page0127.에 꽂힌 책 · 최근 등록 순" | `global_books` 최근 등록 표지 24권 (`cover_image` not null, `created_at desc`) |
| 2 | 선언문 | 라벨 "왜 page0127.인가요" · 큰 문장이 스크롤에 따라 단어 단위로 채워짐 | 정적 문구 |
| 3 | 세 걸음 | 라벨 "이용 방법" · 제목 "책장 하나가 자라는 세 걸음." · **탭(위) → 브라우저 창 패널 → 설명** · 같은 책장이 1 → 7 → 12권으로 자람 | 책등: 최근 등록 도서의 `spine_image` / 나머지 데모 문구 |
| 4 | 보이는 것들 | 라벨 "더 둘러보기" · 제목 "책장이 쌓이면 보이는 것들." · **3열 그리드 6카드**(독서 궁합 · 인생책 · 공개 서재 · 이번 주 많이 읽힌 책 · 피드 · 주간 회상), 카드 하나에 메시지 하나, 굵은 리드 문장 | 랭킹·표지만 실제, 사람 이름·활동은 데모(혜진·준호·서연) |
| 5 | 숫자 | "1,284권 / 지금까지 기록된 책" · "153명 / 함께 읽는 리더" · "412번 / 맞춰 본 독서 궁합" | §5 집계 |
| 6 | 업데이트 | 라벨 "업데이트" · 제목 "계속 자라는 중." · 최신순 세로 타임라인, 최신 항목만 파란 점 | `CHANGELOG` (siteInfo.ts) 그대로 |
| 7 | 마무리 | 파란 무대 · "오늘 읽은 한 권부터 꽂아 보세요." · **카카오/구글 시작 버튼** · "무료 · 10초 가입 · 언제든 탈퇴" · 책이 떨어져 꽂히는 미리보기 | `OAuthLoginButtons` 재사용 |

**삭제**: "한 사람이 만들고 있어요" 섹션(설득 페이지에서 가입을 망설이게 함).

**개인정보**: 피드·궁합 카드에 실제 사용자 이름·활동을 싣지 않는다. 데모 이름만 쓴다.

## 4. 인터랙션 · 접근성 규칙

- **기능 없는 호버 금지.** 표지 확대·기울기·마우스 추적 효과는 넣지 않는다.
- **흐르는 표지 띠**: 마우스를 올리면 멈춘다(WCAG 2.2.2). 각도 없이 평면.
- **세 걸음 탭** (ARIA Tabs 패턴)
  - DOM 순서: `tablist` → `tabpanel`. 탭은 패널 **위**.
  - 화살표 좌우·Home·End로 이동, 선택 탭만 `tabIndex=0`, `aria-controls`/`aria-labelledby` 연결.
  - 자동 재생: 패널이 40% 이상 보일 때만 5.2초 간격으로 넘김. 처음 보일 때 1단계부터 시작.
  - **사용자가 탭을 고르면 자동 재생을 끈다.** 일시정지 버튼(`aria-label` "자동 재생 일시정지/시작").
  - 키보드 포커스가 영역 안에 있으면 잠시 멈춤. **마우스 오버로는 멈추지 않는다**
    (보는 동안 마우스가 위에 있어 '보고 있을 때 재생 안 됨'이 됐던 시안 v7 초판의 실수).
  - 멈춘 상태에서는 항상 완성된 화면을 보여 준다(빈 별·빈 메모 금지).
- `prefers-reduced-motion: reduce`: 모든 애니메이션·자동 재생 끔, 완성 상태로 표시.
- 줄바꿈: 제목·문단·목록·날짜에 `text-wrap: balance`.
- 시맨틱: h1은 히어로 하나, 섹션마다 h2.

## 5. 숫자 섹션 집계

| 값 | 쿼리 | 비고 |
|---|---|---|
| 기록된 책 | `books` 전체 행 수 | 재독도 한 권씩 센다 |
| 함께 읽는 리더 | 책을 1권 이상 기록한 `profiles` 수 | 가입만 하고 떠난 계정 제외 |
| 맞춰 본 독서 궁합 | `ai_usage_logs where feature='compatibility'` 행 수 | |

- RLS 때문에 익명 클라이언트로는 전체를 셀 수 없다 → **SECURITY DEFINER RPC 하나**(`get_about_stats`)로
  세 숫자만 돌려준다. 공개 여부가 걸린 집계는 `is_public` 조건을 쿼리에 직접 적는다는 기존 원칙을 따른다
  (여기 세 값은 개수만 내보내므로 공개 여부와 무관하게 전체를 센다 — 행 내용은 나가지 않는다).
- 페이지는 정적 생성 + `revalidate = 3600`(1시간). 매 요청 집계하지 않는다.
- **노출 기준**: 기록된 책 1,000권 이상 **그리고** 리더 100명 이상일 때만 섹션을 보인다.
  기준 미달이면 섹션 전체를 숨긴다(작은 숫자는 역효과). 기준값은 상수로 둔다.
- 새 마이그레이션이 생기므로 **개발 DB에 먼저 적용한 뒤** PR을 올린다(적용 전엔 CI E2E가 실패한다).
  마이그레이션 번호는 `origin/main`과 겹치지 않는지 확인한다.

## 6. 디자인 규칙 (통일감)

- **색**: 디자인 토큰만. 강조는 파랑 그라디언트 하나(`#2a78de → #1e69cb → #0b4aa8`)를 히어로 무대·궁합 카드·숫자·마무리에 공용.
  예외는 카카오 노란 버튼 하나(브랜드 가이드).
  그라디언트는 기존 원색 `blue-500 → blue-600 → blue-700`(+ 빛 번짐 `blue-400`)로 만든다 — 새 hex 없음.
  `packages/ui/src/styles/index.css`에 `--stage-*` 변수와 `.stage-blue` 유틸을 둔다(`tint-editorial`·`band-strong` 전례).
  흰 글자를 얹는 면이라 다크에서도 같은 값을 쓴다(primary 는 다크에서 밝아져 흰 글자가 안 읽힌다).
- **라운드 3단계**: 큰 면 24px · 안쪽 카드 16px · 버튼/작은 칸 12px · 알약/원. 책등·표지·막대는 실물 흉내라 예외.
- **글자**: 07 타이포 스케일을 따른다 — weight 400/500/700 세 단계, 자간 조정 없음, 임의 크기(`text-[NNpx]`) 금지.
  스케일 최대값(display 28px)으로는 시안의 임팩트가 안 나오므로 **마케팅 전용 한 단계 `display-xl`(데스크톱 48/60 · 모바일 32/42, 700)을
  디자인 토큰에 정식 추가**한다. 소개 페이지의 h1·섹션 제목·선언문만 쓴다. 큰 숫자는 07의 `stat` 역할(이름 있는 크기 `text-5xl`·`text-6xl`).
  시안의 600·−0.03em 자간·19px 문단은 각각 700/500 · 자간 없음 · 16px로 옮긴다.
- **배경 교대**: 흰 → 흰 → 회색(세 걸음) → 흰(보이는 것들·숫자) → 회색(업데이트) → 흰(마무리).
- **다크 모드**: 앱은 OS 설정을 따른다. 토큰만 쓰면 따라오므로 별도 디자인은 하지 않되, 대비는 확인한다.

## 7. 진입로

- 랜딩(`/`) 하단 시작하기 밴드 옆에 "어떻게 쓰나요?" → `/about#steps`.
- 히어로 "어떻게 쓰나요?" 버튼도 같은 앵커.
- 푸터·sitemap은 이미 있음.

## 8. 테스트

- vitest: 숫자 노출 기준 판정 함수, 세 걸음 진행도 → 화면 상태 계산 함수(순수 함수로 분리).
- Playwright(e2e): 탭 키보드 조작·자동 재생 정지·`prefers-reduced-motion`에서 완성 상태 표시.
- 시안에서 쓴 검증 시나리오 6개(마우스 오버 중 재생 포함)를 그대로 옮긴다.

## 9. 작업 단위 (커밋 하나 = diff 100~200줄)

1. 섹션 머리·`Reveal`·balance 공통 조각 + 디자인 토큰(그라디언트·라운드)
2. 히어로 + 최근 표지 띠(서버 조회)
3. 선언문(단어 채움)
4. 세 걸음 — 진행도 계산 순수 함수 + 테스트
5. 세 걸음 — 탭·패널 UI와 접근성
6. 보이는 것들 그리드
7. 숫자 — RPC 마이그레이션 + 노출 기준 + 테스트
8. 업데이트 타임라인(CHANGELOG) + 마무리 CTA
9. 랜딩 진입 링크 + e2e

## 10. 확정된 결정 (2026-10-04)

1. **세 걸음 화면의 컴포넌트**: 취향 카드는 실제 `TasteExampleCard`를 그대로 넣는다(타이핑 연출 없음).
   기록 카드·목표 카드·책장은 **앱과 같은 토큰으로 만든 데모 전용 컴포넌트**다. 책장은 **실제 책등 이미지**(`global_books.spine_image`)를 쓴다.
   - 실제 `PublicBookShelf`를 쓰지 않는 이유(계획 작성 중 발견): 책마다 그 사용자의 책 상세로 가는 **링크**가 걸리고 높이가 240px로 고정이다.
     데모 창에 넣으면 존재하지 않는 서재로 가는 링크가 생긴다.
   - 실제 `ReadingProgressOverview`는 차트까지 포함해 창 안에서 읽히지 않는다.
2. **브랜드 표기 `page0127.`**: 이 페이지 안에서만 적용. 앱 전체 전환은 **별도 작업**.
3. **시안 파일 보관**: `docs/superpowers/specs/assets/2026-10-04-about-mockup-v7.html`로 함께 남긴다.
4. **타이포 스케일 확장**: `display-xl` 한 단계 추가(§6).
