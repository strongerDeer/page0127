# 팔로우 전 지난 나와 배틀

## 동작

- 팔로우 0명은 지난달·작년의 나와 권수·쪽수를 비교한다. 지난달 기록이 없고 작년 기록이 있으면 작년을 먼저 연다.
- 다른 리더와 비교하기 → 최근 공개 책장 추천 → 팔로우하고 비교하기 → 같은 영역에서 올해 팔로잉 비교로 전환한다.
- 추천에서 돌아와도 선택한 기간·지표를 유지한다. 마지막 팔로잉을 해제하면 다시 지난 나와 비교한다.
- 과거 기록이 없거나 완독 날짜가 부족하면 승패나 0 대 0 게이지 대신 내 올해 공개 완독과 리더 찾기를 보여준다.
- 팔로우 요청이 실패하면 비교 모드를 바꾸지 않는다. 팔로우 성공 후 집계 조회가 실패하면 팔로우 완료 사실과 올해 기록 재시도를 표시한다.

## 비교 기준

- 서울 기준 오늘까지의 달력 날짜를 맞춘다. 예: 10/1~10/26 대 9/1~9/26, 올해 1/1~10/26 대 작년 1/1~10/26.
- 이전 달에 없는 날짜와 윤년의 2/29는 말일로 맞춘다. 1월의 지난달은 작년 12월이다.
- 본인 공개 완독 중 정확한 완독 날짜가 있는 기록만 비교한다. 연도만 있는 기록은 기간 점수에서 제외하고 정보 아이콘에서 따로 알린다.
- 먼저 기간을 자른 뒤 서재와 같은 ISBN/ID·대표 회독 선택 규칙을 사용한다. 같은 책도 서로 다른 비교 기간에는 각각 한 권이다.
- 쪽수는 대표 완독 기록의 page_count 합계다. 쪽수가 없는 책도 권수에는 포함한다. 쪽수가 미등록된 기록이 있으면 승패와 우열을 표현하는 게이지를 중립화한다.
- 팔로우 후에는 기존 RPC의 올해 공개 완독 집계로 바뀐다. 전환 안내로 기간이 달라졌음을 알린다.

## 데이터와 배포

새 마이그레이션은 없다. 기존 RLS와 팔로우 API를 사용한다. 본인의 최근 두 연도 공개 완독에서 집계에 필요한 열만 가져온다. 실제 반환 수·전체 건수·중복 ID를 확인하며 페이지를 나눠 읽고, 불완전한 조회를 0권으로 처리하지 않는다.

서버 초기 조회와 브라우저 재조회가 같은 순수 집계 함수를 사용한다. 팔로우 0명일 때만 이 조회를 켜고, 팔로잉 비교에서는 기존 집계 RPC를 사용한다. 서버·클라이언트 모두 날짜를 포함한 캐시 키/응답을 확인하며 페이지 재진입·탭 복귀 때 갱신한다.

## 검증

- 월말·윤년·1월·서울 날짜 경계, 공개/비공개·완독/진행 중·타인·미래 날짜, 회독별 쪽수·ISBN 미상·완독 연도만 있는 기록 검증
- 반환 행 제한·도중 건수 변화·누락·중복 페이지·네트워크 오류 검증
- Storybook의 팔로우 버튼 요청은 Axios 어댑터로 대체한다. 실제 팔로우를 만들지 않고 성공·실패와 전환 콜백을 검증한다.
- 최신 main 통합 후 단위 테스트 1,244개 및 Storybook 171개 통과, 프로덕션 빌드 통과
