## 1. 접근성 (CRITICAL)

가장 먼저 본다. 여기서 걸리면 다른 게 아무리 좋아도 못 쓰는 사람이 생긴다.

- [ ] **색 대비 4.5:1** — 본문 텍스트 기준. 큰 텍스트(18pt+ 또는 14pt bold)는 3:1
- [ ] **포커스 링이 보인다** — 키보드 Tab으로 이동할 때 지금 어디인지 보여야 한다. `outline: none`만 주고 대체 스타일을 안 넣는 게 가장 흔한 실수
- [ ] **아이콘만 있는 버튼에 `aria-label`** — 스크린리더는 아이콘을 읽지 못한다
- [ ] **의미 있는 이미지에 `alt`** — 장식용이면 `alt=""`로 명시적으로 비운다
- [ ] **Tab 순서 = 시각적 순서** — CSS로 순서를 바꿨다면 DOM 순서도 맞춘다
- [ ] **`<label htmlFor>` 연결** — placeholder는 label이 아니다
- [ ] **제목 계층이 h1→h6 순서** — h2 다음에 h4로 건너뛰지 않는다
- [ ] **색만으로 정보를 전달하지 않는다** — 빨강=오류라면 아이콘이나 텍스트도 함께
- [ ] **`prefers-reduced-motion` 존중** — 어지럼증을 유발할 수 있다
- [ ] **모달에 닫기 경로** — ESC, 바깥 클릭, 닫기 버튼 중 최소 하나
- [ ] **본문 바로가기 링크(skip link)** — 키보드 사용자가 네비게이션을 매번 통과하지 않도록

> ⚠️ **현황**: `aria-label` 25곳 사용 중. `prefers-reduced-motion` 4곳 대응.
> shadcn(Radix) 컴포넌트는 포커스·ARIA가 기본 내장이라 **직접 만든 컴포넌트가 위험 구간**이다.

## 2. 상호작용 (CRITICAL)

- [ ] **클릭 영역 최소 44×44px** — 아이콘이 작으면 padding으로 넓힌다. 시각적 크기와 클릭 영역은 별개
- [ ] **클릭 요소 사이 8px 이상 간격** — 오터치 방지
- [ ] **hover에만 의존하지 않는다** — 터치 기기엔 hover가 없다. 툴팁으로만 정보를 주면 모바일에서 사라진다
- [ ] **비동기 중 버튼 비활성화 + 스피너** — 중복 제출 방지. **비활성화는 버튼에만 건다** —
      입력창까지 `disabled` 하면 포커스가 날아간다 (§8 참조)
- [ ] **클릭 가능한 요소에 `cursor-pointer`**
- [ ] **오류 메시지는 문제가 생긴 곳 근처에** — 페이지 최상단에만 띄우면 못 찾는다
- [ ] **`touch-action: manipulation`** — 모바일 브라우저의 300ms 탭 지연 제거

> 💡 **왜 44px인가**: 성인 검지 끝의 평균 접촉 면적이 약 45px다. Apple·Material 양쪽이 같은
> 근거로 44/48을 제시한다. 데스크톱 전용 화면이라도 노트북 터치스크린을 고려하면 지키는 게 낫다.

## 3. 성능 (HIGH — Core Web Vitals)

- [ ] **이미지에 `width`/`height` 또는 `aspect-ratio` 선언** — 없으면 로드되며 레이아웃이 밀린다(CLS)
- [ ] **WebP/AVIF + 반응형 이미지** — `next/image`가 자동 처리
- [ ] **폰트 `font-display: swap`** — 폰트 로딩 중 텍스트가 안 보이는 현상(FOIT) 방지
- [ ] **중요 폰트만 preload** — 모든 변형을 preload하면 오히려 느려진다
- [ ] **비필수 컴포넌트는 `dynamic import`** — 라우트/기능 단위 코드 분할
- [ ] **비동기 콘텐츠 자리 미리 확보** — 스켈레톤으로 높이를 잡아둔다
- [ ] **접힘선 아래 이미지는 `loading="lazy"`**
- [ ] **50개 이상 리스트는 가상화 검토**
- [ ] **1초 넘는 작업엔 스켈레톤** — 무한 스피너보다 체감이 낫다
- [ ] **스크롤·리사이즈·입력 이벤트에 debounce/throttle**

> ⚠️ **현황**: `next/image` 24곳 사용, **`<img>` 직접 사용 0곳** — 이미지 최적화는 잘 지켜지고 있다.
> 이미 자체 RUM(web-vitals)과 품질 대시보드가 돌고 있으니, 이 항목들은 **감으로 판단하지 말고
> 대시보드 수치로 확인**한다.

## 4. 레이아웃 & 반응형 (HIGH)

- [ ] **본문 최소 16px** — 그보다 작으면 iOS Safari가 입력 시 자동 확대한다
- [ ] **한 줄 길이 제한** — 모바일 35~60자, 데스크톱 60~75자. 너무 길면 다음 줄을 찾기 어렵다
- [ ] **모바일에서 가로 스크롤 없음** — 375px에서 확인
- [ ] **breakpoint 일관성** — 375 / 768 / 1024 / 1440
- [ ] **4/8px 배수 간격 체계** — 임의 값(13px, 27px) 금지
- [ ] **데스크톱 컨테이너 최대 너비 고정** — 페이지마다 다르면 어색하다
- [ ] **z-index 단계 정의** — 0 / 10 / 20 / 40 / 100 / 1000처럼 미리 정해두지 않으면 `z-9999` 전쟁이 난다
- [ ] **`100vh` 대신 `min-h-dvh`** — 모바일 주소창 때문에 100vh는 화면을 넘긴다
- [ ] **고정 헤더/바 아래 콘텐츠가 가려지지 않게 padding 확보**
- [ ] **위계는 크기·간격·대비로** — 색만으로 위계를 만들지 않는다

## 5. 타이포그래피 & 색 (MEDIUM)

- [ ] **본문 `line-height` 1.5~1.75**
- [ ] **타입 스케일 고정** — 12 / 14 / 16 / 18 / 24 / 32
- [ ] **굵기로 위계 강화** — 제목 600~700, 본문 400, 라벨 500
- [ ] **시맨틱 색 토큰 사용** — 컴포넌트에 raw hex를 직접 쓰지 않는다
- [ ] **전경/배경 쌍이 4.5:1 충족** — 도구로 실제 측정
- [ ] **숫자 열엔 tabular figures** — 값이 바뀔 때 자릿수가 흔들리지 않는다 (통계·평점 화면에서 중요)
- [ ] **자르기보다 줄바꿈 우선** — 잘라야 한다면 말줄임 + 전체 텍스트 접근 수단 제공

> ⚠️ **현황**: `.tsx` 안에 하드코딩된 hex가 **24곳**. 디자인 토큰 패키지를 두고 있으므로
> 이건 정리 대상이다. (단, 차트 색상처럼 토큰화가 애매한 경우가 섞여 있을 수 있으니 일괄 치환 금지 —
> 한 곳씩 열어보고 판단할 것)

## 6. 다크 모드

> ⚠️ **현황(2026-07-29 재측정): 다크모드는 구현되어 있다.** 아래는 지금 지킬 항목이다.
>
> 적용 방식은 **CSS 변수 재정의**다 — `@repo/design-tokens/tokens-dark.css` 가
> `@media (prefers-color-scheme: dark) { :root { … } }` 로 토큰 값을 통째로 덮는다.
> **OS 설정을 따르며 앱 안에 토글은 없다.**
>
> 그래서 Tailwind `dark:` 유틸 사용은 **0곳**이다 — 빠뜨린 게 아니라 필요가 없다.
> 컴포넌트는 시맨틱 토큰만 쓰고, 값이 갈리는 건 토큰 레이어다. 이 방식의 함의:
>
> - **새 컴포넌트에서 `dark:` 를 쓰기 시작하지 않는다.** 토큰을 쓰면 자동으로 따라온다.
>   `dark:` 를 쓰는 순간 다크 값이 두 군데(토큰 + 클래스)로 갈라진다.
> - 토큰으로 표현이 안 되는 예외만 CSS에서 직접 분기한다. 현재 그런 예외는
>   `globals.css` 의 `.book-cover` 한 곳뿐이다.
> - `next-themes` 는 여전히 `sonner.tsx`(토스트) 한 곳에서만 import된다.
>   **앱 내 테마 토글을 도입하려면** OS 설정만 보는 지금 구조를 먼저 바꿔야 한다.

- [ ] 라이트 값을 반전하지 않는다 — 채도를 낮춘 톤 변형을 따로 만든다
- [ ] 다크에서 대비를 **독립적으로** 다시 측정한다 (라이트에서 통과했다고 넘어가지 않는다)
- [ ] 구분선·테두리가 양쪽 모드에서 모두 보인다
- [ ] hover/focus/disabled 상태가 양쪽에서 동등하게 구별된다
- [ ] 모달 스크림 40~60% — 뒤 배경이 시각적으로 경쟁하지 않게

> 💡 **판단**: "절반만 구현"이 가장 나쁘다는 이유로 전면 도입을 택했다. 그래서 이제 남는 위험은
> 반대쪽이다 — **개발은 라이트에서만 하면서 다크가 깨진 걸 아무도 모르는 것.** 토글이 없어
> OS 설정을 바꿔야만 볼 수 있으니 더 잘 방치된다. 새 화면을 만들면 macOS 시스템 설정에서
> 다크로 한 번 전환해 눈으로 확인한다.

## 7. 애니메이션 (MEDIUM)

- [ ] **마이크로 인터랙션 150~300ms**, 복잡한 전환도 400ms 이내
- [ ] **`transform`/`opacity`만 애니메이션** — `width`/`height`/`top`/`left`는 리플로우를 일으킨다
- [ ] **진입 `ease-out`, 이탈 `ease-in`** — UI 전환에 `linear`는 기계적으로 느껴진다
- [ ] **이탈은 진입의 60~70% 길이로** — 빠져나갈 때 굼뜨면 답답하다
- [ ] **한 화면에 움직이는 요소 1~2개**
- [ ] **모든 애니메이션은 중단 가능** — 사용자가 클릭하면 즉시 취소
- [ ] **애니메이션 중 입력을 막지 않는다**
- [ ] **리스트 등장은 항목당 30~50ms 시차**
- [ ] **애니메이션이 CLS를 만들지 않는다**
- [ ] **장식용 애니메이션 금지** — 모든 움직임은 인과관계를 표현해야 한다

## 8. 폼 & 피드백 (MEDIUM)

- [ ] **입력마다 보이는 label** — placeholder 단독 금지 (입력 시작하면 사라진다)
- [ ] **오류는 해당 필드 아래에**
- [ ] **제출 시 로딩 → 성공/실패 상태 표시**
- [ ] **필수 항목 표시**
- [ ] **검증은 blur 시점에** — 타이핑 중 매 글자마다 빨갛게 만들지 않는다
- [ ] **오류 메시지에 원인 + 해결 방법** — "잘못된 입력"만으로는 아무것도 못 한다
- [ ] **시맨틱 input type** — `email`, `tel`, `number`가 모바일 키보드를 바꾼다
- [ ] **비밀번호 표시/숨김 토글**
- [ ] **`autocomplete` 속성** — 브라우저 자동완성 지원
- [ ] **파괴적 작업 전 확인**, 가능하면 **실행 취소** 제공
- [ ] **토스트 3~5초 자동 사라짐 + 포커스를 뺏지 않음** (`aria-live="polite"`)
- [ ] **제출 실패 시 첫 오류 필드로 자동 포커스**
- [ ] **빈 상태에 안내와 행동 유도** — 텅 빈 화면만 보여주지 않는다
- [ ] **읽기 전용과 비활성을 구분** — 둘은 다른 의미다
- [ ] **로딩 중에 입력창 자체를 `disabled` 하지 않는다** — 브라우저는 disabled 된 요소에서
      포커스를 **강제로 제거**하고, 풀려도 돌려주지 않는다. 비활성화는 제출 버튼에만 건다

> 💡 **실제로 겪은 것** (2026-07-29, `/books/add`): 검색창이 `disabled={isLoading}` 이었는데
> 400ms 디바운스 자동 검색이 **타이핑 도중에** 걸렸다. 입력창이 죽었다 살아나며 포커스가
> 사라지고 그 사이 누른 키가 씹혔다. 증상은 "입력이 자꾸 끊긴다"로 보고됐지만 원인은 포커스였다.
> 디바운스 자동 검색·자동 저장처럼 **사용자가 아직 입력 중일 때 로딩이 시작되는 UI**에서 특히
> 위험하다. 입력창을 열어두면 요청이 겹칠 수 있으니, 막는 대신 **마지막 응답만 반영**한다.

> ⚠️ **현황**: 폼/입력을 쓰는 파일 15개. 회원가입·책 기록·리뷰 등 사용자 입력이 핵심 동선이라
> 이 섹션은 실제로 훑을 가치가 있다.

## 9. 네비게이션 (HIGH — 웹 해당분만)

- [ ] **현재 위치가 시각적으로 표시된다**
- [ ] **뒤로 가기가 예측 가능하고 스크롤·필터 상태를 복원한다**
- [ ] **주요 화면이 URL로 도달 가능** — 공유·알림 링크의 전제
- [ ] **3단계 이상 깊이엔 breadcrumb**
- [ ] **네비게이션 위치가 페이지마다 바뀌지 않는다**
- [ ] **모달을 주요 이동 경로로 쓰지 않는다**
- [ ] **위험한 작업(탈퇴·로그아웃)은 일반 메뉴와 시각적·공간적으로 분리**
- [ ] **1024px 이상은 사이드바, 작은 화면은 상단/하단 네비**
- [ ] **라우트 변경 후 포커스를 본문으로 이동** — 스크린리더 사용자를 위해
- [ ] **액션이 공간을 넘치면 더보기 메뉴로**

## 10. 차트 & 데이터 (Recharts)

> page0127은 Recharts 차트가 **6개** 있다:
> `RumTrendChart` · `FieldTrendChart`(어드민 품질), `MonthlyReadingChart` ·
> `CategoryRadarChart` · `CategoryBarChart` · `YearlyTrendChart`(통계)

- [ ] **데이터 유형에 맞는 차트** — 추세→선, 비교→막대, 비율→파이
- [ ] **파이/도넛은 5개 카테고리까지** — 넘으면 막대가 낫다
- [ ] **범례를 항상 표시하고 차트 근처에 둔다**
- [ ] **툴팁으로 정확한 값 제공**
- [ ] **축에 단위와 읽을 수 있는 눈금** — 모바일에서 라벨이 잘리거나 회전하지 않게
- [ ] **작은 화면에서 차트가 단순화된다** — 세로 막대 → 가로 막대, 눈금 줄이기
- [ ] **빈 데이터 상태** — 빈 축만 덩그러니 두지 않고 "아직 데이터가 없어요" + 안내
- [ ] **로딩 중 스켈레톤** — 빈 축 프레임을 먼저 보여주지 않는다
- [ ] **데이터 로드 실패 시 오류 + 재시도**
- [ ] **색에만 의존하지 않는다** — 적/녹 조합은 색각 이상 사용자에게 구분되지 않는다. 패턴·모양·직접 라벨 병행
- [ ] **데이터 선/막대 대비 3:1 이상**, 데이터 라벨 텍스트 4.5:1 이상
- [ ] **그리드 선은 옅게** — 데이터와 경쟁하지 않게
- [ ] **차트 등장 애니메이션도 `prefers-reduced-motion` 존중**
- [ ] **스크린리더용 요약 제공** — 차트의 핵심 인사이트를 `aria-label`이나 텍스트로
- [ ] **접근성 대안으로 표 제공** — 차트만으로는 스크린리더가 읽지 못한다
- [ ] **숫자·날짜·통화는 locale 기준 포맷**

> ⚠️ **주의**: Recharts 3 + React 19 조합에서 리렌더 burst가 보고된 적이 있다.
> 차트가 많은 화면은 React DevTools "Highlight updates"로 한 번 점검할 것.

## 오픈 전 최소 통과 기준

전부 다 볼 시간이 없다면 이것만은 확인한다.

- [ ] 375px 폭에서 가로 스크롤이 없다
- [ ] 키보드 Tab만으로 주요 동선(로그인 → 책 기록 → 저장)이 완주된다
- [ ] 포커스 링이 모든 단계에서 보인다
- [ ] 아이콘만 있는 버튼에 전부 `aria-label`이 있다
