# 라운지 피드·배틀 확장

## 화면과 동작

- PC는 왼쪽 피드·오른쪽 배틀의 2열, 모바일은 피드·배틀 탭 구성이다. 기존 `/feed` 주소를 유지한다.
- 콕 찌르기는 팔로우하는 상대에게 고정 문구와 선택한 내 공개 독서 기록을 보낸다. 앱 내 알림이며 같은 상대에게 서울 기준 하루 한 번이다. 수신자는 설정에서 끌 수 있다.
- 읽는 중 등록은 `/books/add?status=reading`으로 기존 검색·등록 흐름에 연결한다. 기존 기록 수정은 저장된 상태를 우선한다.
- 장르 문어발은 올해 공개 완독을 ISBN(없으면 ID)으로 합치고 서재의 대분류로 센다. 기타·분류 미상은 제외한다.
- 취향 대격돌은 완독 연도와 관계없이 두 사람이 공개 완독한 같은 ISBN의 최신 대표 회독을 비교한다. 별점이 서로 다른 책 중 차이가 큰 책을 보여준다.
- 시상대는 1등 파랑·2등 민트·3등 옅은 파랑이다. 0권도 포함하고 동점은 같은 순위의 색상과 높이를 사용한다.
- 콕 찌르기 아이콘은 상대 프로필 오른쪽에 둔다. 1:1에서 상대의 올해 공개 완독이 0권이면 대기 문구 대신 콕 찌르기 버튼을 보여준다.
- 집계 기준은 제목 옆 정보 아이콘의 호버·포커스·탭으로 확인한다. 장르별 상세 목록은 표시하지 않는다.

## DB 선반영 완료

사용자 요청에 따라 운영 `page0127`과 CI `page0127-dev`에 `20261025000003_lounge_social_battles.sql`을 적용했다. 두 DB 모두 dry-run에서 이 파일 한 개만 미적용임을 확인한 뒤 반영했다.

원격 DB에 별도로 조회해 확인한 결과:

- 마이그레이션 `20261025000003` 적용 이력 존재
- `get_following_reading_social`, `send_reading_nudge`: SECURITY DEFINER, 빈 search_path 고정
- 두 함수 실행 권한: anon 불가, authenticated 가능
- `reading_nudge_settings`, `reading_nudge_limits`: RLS 활성화
- 로그인 세션 없는 소셜 집계 응답: null

CLI의 pg-delta 카탈로그 캐시 경고는 있었으나 실제 적용 이력과 메타데이터 조회로 성공을 확인했다. 운영·CI에서 테스트 알림을 보내거나 사용자 독서 기록을 생성하지 않았다. 코드는 EXPECTED_MIGRATION_VERSION을 `20261025000003`으로 올린다.

## 검증

- PGlite: 공개/비공개, 재독 대표 선택, 완독 연도만 있는 기록, 팔로우 0명, 비로그인, 수신 거부, 하루 중복 제한, 직접 INSERT 우회와 권한 검증
- 단위 테스트: 185개 파일, 1,222개 테스트 통과
- Storybook: 157개 테스트 통과, 문서 전용 파일 하나 제외
- 변경 파일 포맷·ESLint 및 TypeScript 검사 통과
- Next.js 프로덕션 빌드 통과. 로컬 대체 DB 설정으로 검증했다.
- PC·모바일 가로 넘침 없음 및 시상대 색상 확인

코드 배포 후 로그인한 `/feed`에서 수신 설정·실제 상호작용을 확인한다. 운영 알림 발송을 이용한 자동 테스트는 수행하지 않는다.
