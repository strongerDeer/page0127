## 🟠 P1 — 첫 5분 경험 (지금 아니면 못 본다)

- [ ] **8. 빈 상태 화면** — 0권 유저가 보는 대시보드·피드·랭킹·취향 분석. 데이터가 적은 **지금이
      유일하게 확인 가능한 시기**다. "오늘 0권 완독" 같은 억지 문구가 없는지도 함께 본다.
- [ ] **9. 카카오 로그인 — 베타에 넣는다** (2026-08-25 결정). 사람들이 카카오로 가장 많이 가입할
      것으로 보고, 기본 흐름은 이미 사용자가 테스트했다. **문제는 베타에서 잡는다.**
      다만 아래는 카카오에만 있는 함정이라 첫 가입자를 특히 지켜본다.
      - 카카오는 **이메일을 아예 주지 않는다** → 계정 연동·온보딩 분기가 구글과 다른 길을 탄다
      - 같은 사람이 구글로 먼저 가입한 뒤 카카오로 들어오면 **별개 계정**이 된다
      - ⚠️ `@repo/icons` 는 CSP 에 막혀 앱에서 못 쓴다 (버튼 아이콘 확인)
- [ ] **10. username 정책** — 이메일 로컬파트 기반 자동 생성 + 설정 화면에서 **변경 불가**.
      베타 유저가 가장 먼저 말할 불만이다. **카카오 가입자는 이메일이 없으므로 생성 규칙이 어떻게
      도는지 반드시 확인**(9번과 함께). ⚠️ 최상위 라우트와 겹치면 그 서재에 영영 못 들어간다 —
      `admin api auth login about books contact privacy terms dashboard feed notifications
      search settings`
- [ ] **11. 다크 모드 실물 확인** — 코드는 병합됐으나(OS 설정 기반) 각 화면을 다크로 본 기록이
      없다. 대시보드 차트색(`chart-1~5`)도 함께.
- [ ] **12. 책 공개/비공개 기본값** — 새 유저가 등록한 책이 기본 공개인지, **그 사실이 화면에
      보이는지.** 모르고 공개되면 기능 버그가 아니라 신뢰 사고다.
- [ ] **13. 문의 동선** — 카카오 오픈채팅 링크가 살아 있는지 + `/contact` 가 눈에 띄는 자리에
      있는지. 베타는 **피드백이 목적**인데 창구가 안 보이면 아무도 말해주지 않는다.

## 🟡 P2 — 베타를 돌리며 관찰

- [ ] **14. 신고(reports) → 어드민 처리 흐름 1회 리허설** — 남의 글이 처음 생기는 시점이다.
- [ ] **15. rate limit 이 fail-open** — `increment_rate_limit` RPC 가 실패하면 요청을 막지 않는다.
      DB 가 흔들리면 전부 통과한다는 뜻. AI 엔드포인트에 별도 과금 가드가 있는지 재확인.
      (현재 티어: strict 5 / search 20 / standard 60 / beacon 120)
- [ ] **16. 어드민 접근 제어** — 베타 유저가 `/admin` 을 찍어봤을 때.
- [ ] **17. 퍼널 지표** — "몇 명 들어와 몇 명이 첫 책을 등록했나"를 보는 화면이 없다(D-2 미구현).
      최소한 GA·자체 RUM 으로 사후 집계는 되는지 확인해 둔다. 방문 기록은 이미 쌓이는 중이라
      화면은 몇 주 뒤에 만들어도 그때까지가 전부 보인다.
- [ ] **18. uptime 감시 간격** — GitHub Actions cron 이라 실제로는 10~20분 간격이다. 베타 규모면
      충분하나 **알고는 있을 것**. 분 단위가 필요해지면 전용 서비스로 옮긴다.
- [ ] **19. Supabase free 플랜 한도** — DB 용량·대역폭·월 활성 사용자. 베타 인원 대비 여유 확인.
