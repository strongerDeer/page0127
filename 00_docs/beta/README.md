# 첫 베타 운영안

작성: 2026-10-24. 이 폴더는 모집·참여 안내·피드백 문안과 빈 운영 기록 양식이다. 실제 참가자 정보와 설문 응답은 공개 저장소에 넣지 않는다.

## 운영 기준

- 초안 기준: 10명, 참여 시작일부터 2주, 참여비 없음·별도 사례비 없음. 게시 전에 운영자가 이 조건을 확정한다.
- 먼저 3명에게 안내하고 가입·저장 흐름을 관찰한 뒤 나머지 7명을 초대한다.
- 책 1권을 스스로 기록하는 경험이 기본이다. AI 분석은 평가한 완독 책 5권을 준비할 수 있는 사람만 선택한다.
- 최근 읽은 책이 여러 권인 사람과 독서 기록을 처음 시작하는 사람이 함께 참여하도록 모집한다.
- 지인 추천·인스타·직접 방문 등 유입 경로와 운영자 도움 여부를 구분한다.
- UptimeRobot은 2026-10-24 사용자 결정으로 도입하지 않는다. 기존 GitHub Actions와 Sentry를 유지하며, GitHub 감시의 과거 실행 간격 3~6시간은 신속한 장애 감지를 보장하지 않는다. [런북](../../apps/page0127/docs/operations-runbook.md) 참조.

## 모집을 시작하기 전

- [ ] 다른 스레드에서 진행하는 선택 유실·실제 담기·가입 후 복귀 문제의 수정과 배포 상태 확인.
- [ ] 실제 휴대폰에서 맛보기 → 가입 → 첫 책 저장 → 평가 → 취향 분석까지 확인. AI는 조건을 충족한 계정으로 확인.
- [ ] 별도 계정에서 비공개 기록이 보이지 않는지 확인.
- [ ] 문의 링크와 운영자 수신 상태 확인.
- [ ] 참여 조건(인원·기간·참여비·사례비)을 확정하고 모집 문구와 일치시킴.
- [ ] 공개 기록 기본값과 AI 분석 5권 조건을 안내에 포함.
- [ ] 최근 백업 성공 확인. 기존 복원·Sentry 검증은 반복하지 않고 변경된 경로만 재확인.

## 진행 순서

1. 첫 3명: 설명을 덧붙이기 전에 직접 사용하도록 하고 막힌 화면과 이유를 기록한다. 도움이 필요하면 제공하고 도움 여부를 남긴다.
2. 가입 불가·기록 유실·비공개 노출이 있으면 추가 초대를 멈추고 먼저 수정한다.
3. 남은 7명: 같은 안내로 초대한다. 중간에 화면을 바꿨다면 날짜·배포 버전과 영향을 받은 참가자를 기록한다.
4. 1주: 자발적 재방문을 먼저 확인한다. 사전에 동의한 사람에게만 중간 질문을 보내며, 그 뒤의 방문은 요청 후 방문으로 구분한다.
5. 2주: 종료 질문을 받고 개선할 문제 3개만 고른다.

## 결과를 읽는 법

가입 수보다 첫 책 저장, 실제 재방문, 두 번째 기록, 다시 쓴 이유를 우선한다. 방문만 한 사람과 기록까지 남긴 사람을 구분한다.

내부 관찰 목표(업계 기준 아님):

- 첫 책 저장: 참여를 시작한 10명 중 8명이 운영자 도움 없이 성공.
- W1 재방문: 첫 책을 저장했고 7일 관찰이 끝난 사람 중 절반 이상이 가입 다음 날부터 7일 안에 자발적으로 방문.
- AI: 조건을 갖춰 시도한 사람의 성공 수/시도 수와 결과에 대한 구체적인 이유 수집. 모든 참가자에게 5권 입력을 요구하지 않는다.

초대 인원·참여 시작 인원·관찰 기간이 끝난 인원을 각각 적는다. 예: “초대 10명, 시작 8명, 첫 책 저장 7/8명”. 작은 표본에서는 비율만 쓰지 않는다.

GA `sign_up`은 온보딩 완료, DB의 `profiles.created_at`은 프로필 생성이다. 둘을 같은 가입 완료 수로 간주하지 않는다. 기존 어드민 W1은 방문 기록이므로 자발성·기록 행동은 비공개 운영 기록과 함께 읽는다.

설문 후속 연락 동의는 베타 질문에만 사용한다. 기능 홍보나 새 모집 알림 동의로 확대하지 않는다.
