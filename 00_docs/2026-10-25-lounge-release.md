# 라운지 독서 리그 반영

- 경로는 기존 `/feed`를 유지하고 모바일·데스크톱 메뉴와 페이지 이름을 라운지로 바꾼다.
- 한 명은 내 기록과 리더 찾기, 두 명은 블루·민트 배틀, 세 명 이상은 시상대와 전체 순위다.
- 연말·월말 결산은 이번 반영 범위에 포함하지 않는다.

## DB 반영 완료

2026-10-25 사용자 요청으로 운영 `page0127`과 CI 테스트용 `page0127-dev`에 `20261025000002_following_reading_league.sql`을 적용했다. 각 DB의 dry-run에서 이 파일 한 개만 미적용임을 확인한 뒤 반영했다.

두 DB에서 직접 확인한 결과:

- 적용 버전: `20261025000002`
- 함수: `SECURITY DEFINER`, 고정된 빈 `search_path`
- 실행 권한: `anon` 불가, `authenticated` 가능
- 세션 없이 함수 호출 시 반환 행: 0개

CLI의 마이그레이션 카탈로그 캐시 경고가 있었지만, 원격 적용 이력과 함수 메타데이터를 별도 조회해 반영 성공을 확인했다. 작업 폴더의 기존 CI DB 연결도 유지했다.

## 코드 배포

DB 선반영은 완료했다. 코드의 `EXPECTED_MIGRATION_VERSION`은 `20261025000002`이며, 코드 배포 후 `/api/health`에서 schema drift 여부를 확인하고 로그인 후 `/feed`를 연다.

## 집계와 갱신

- `auth.uid()`의 본인과 팔로잉만 RPC가 집계한다. 공개 완독 기록만 사용하며 서울 기준 올해, 완독 날짜 우선·완독 연도 대체다.
- 기간을 먼저 고른 뒤 ISBN(없으면 ID)으로 회독을 합친다. 대표 회독의 쪽수를 사용하며 TypeScript 서재 집계와 동률 대표 선택도 맞춘다.
- 조회 실패는 0권이 아니다. 오류와 재시도 버튼을 표시하고 활동 피드는 계속 사용할 수 있게 한다.
- 팔로우 쿼리 무효화, 다른 탭의 팔로우 이벤트, 탭 복귀, 페이지 재진입 때 다시 조회한다.
- 인원이 서버의 반환 행 제한을 넘으면 정확한 전체 인원과 대조하며 페이지를 나눠 받는다. 일부 인원만 받아 순위를 표시하지 않는다.
- 추천은 기존 최근 기록한 리더를 재사용하며 본인·현재 팔로잉·서재 주소가 없는 사람을 제외하고 최대 두 명을 표시한다.

## 확인할 화면

- 팔로우 0명과 내 기록 0권/유효한 기록
- 팔로우 1명, 동점, 한쪽 0권, 쪽수 정보 누락
- 세 명 이상, 공동 순위, 권수·쪽수 전환, 올해 기록이 모두 없는 상태
- 모바일·다크 모드·모션 줄이기
- DB 미반영/장애 시 오류 안내와 피드 분리

SQL 집계 사례는 PGlite에서 검증했다. 운영·CI DB에서는 적용 이력·함수 권한·세션 없는 응답을 조회해 확인했으며, 사용자 기록은 생성하거나 수정하지 않았다.
